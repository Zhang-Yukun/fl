# 结果输出文件字段说明

本文档以当前代码实现为准，说明实验输出目录中的结果文件字段，以及 wandb 中实际记录的标量/图像名称。

适用范围：
- 集中式训练
- 单进程联邦训练
- gRPC 多进程/多节点联邦训练

代码来源：
- `fedlab/federated/algorithms.py`
- `fedlab/federated/server.py`
- `fedlab/communication/grpc_training.py`
- `fedlab/security/attacks.py`
- `fedlab/utils/tracking.py`

## 1. 常见输出文件

| 文件 | 含义 | 模式 |
| --- | --- | --- |
| `summary.json` | 最终摘要，适合做实验对比 | 全部 |
| `metrics.json` | 训练过程明细；集中式为对象，联邦/gRPC 为 round 列表 | 全部 |
| `attack_results.json` | 攻击结果逐条记录 | 联邦/gRPC，且启用攻击 |
| `model.pt` | 联邦/多节点最终全局模型参数 | 联邦/gRPC |
| `centralized_model.pt` | 集中式最终模型参数 | 集中式 |
| `config.yaml` / `config.json` / `config.toml` | 生效配置快照 | 全部 |
| `run.log` | 运行日志 | 全部 |
| `attack_artifacts/` | 攻击重构保存的张量文件 | 联邦/gRPC，且启用攻击 |
| `snapshots/round_xxxx/` | 周期性中间快照 | 启用周期性保存时 |

## 2. 关键通信口径

### 2.1 `parameter_*`

表示**算法有效通信量**：
- 包含模型参数/更新量本体
- 包含恢复这些参数所必须发送的辅助信息
- 例如：
  - 稀疏索引
  - 量化 scale
  - EGA 编码块及恢复所需辅助量
  - EGA 下载 `round_context` 中用于恢复语义 payload 的内容

不包含：
- gRPC / pickle / envelope / 控制字段等纯传输层额外开销

### 2.2 `transport_*`

表示**实际序列化传输量**：
- 包含 `parameter_*`
- 额外包含消息封装、控制字段、RPC 序列化等开销

因此：
- 做算法通信压缩比较，优先看 `parameter_*`
- 做真实部署网络成本分析，优先看 `transport_*`

### 2.3 兼容别名

当前代码中：
- `download_bytes == parameter_download_bytes`
- `upload_bytes == parameter_upload_bytes`
- `total_download_bytes == total_parameter_download_bytes`
- `total_upload_bytes == total_parameter_upload_bytes`

这些 `*_bytes` 字段现在也表示**算法有效通信量**，不是“只含张量本体”的旧语义。

## 6.4 联邦 / gRPC 每轮 wandb 标量字段

这一部分不是“额外生成一套新指标”，而是把每轮 `RoundRecord`、每客户端记录、累计通信统计、攻击统计平铺成 wandb 易于筛选的键空间。

读取时建议按下面四层理解：
- `round/...`：这一轮服务器侧汇总后的主结果，是每轮最核心的曲线来源
- `client/<client_id>/...`：这一轮每个客户端各自的上传、下载、损失与 payload 信息
- `cumulative/...`：从第 0 轮累计到当前轮的通信总量，用来直接看“总通信量随轮数变化”
- `attack/...`：攻击线程完成后补记的攻击结果，既包含当前轮，也包含截至当前的累计隐私表现

### 6.4.1 `round/<RoundRecord字段>`

`round/...` 表示**这一轮联邦聚合完成后，服务器端看到的 round 级结果**。它主要用于画收敛曲线、压缩比曲线、每轮耗时曲线。

可以按功能分成 6 组来读：

1. 训练与验证表现
- `round/train_loss`
- `round/val_mse`
- `round/val_mae`
- `round/val_mape`
- `round/active_val_scope`
- `round/active_val_mse`
- `round/active_val_mae`
- `round/active_val_mape`
- `round/protocol_val_mse`
- `round/protocol_val_mae`
- `round/protocol_val_mape`
- `round/oracle_val_mse`
- `round/oracle_val_mae`
- `round/oracle_val_mape`

说明：
- `round/val_*` 是兼容字段，通常与当前激活验证口径一致。
- 真正建议优先读取的是 `round/active_val_*`，因为它明确表示“当前这轮用于决策的验证口径”。
- 如果启用了 oracle 评测，则同一轮会同时写 `protocol_val_*` 和 `oracle_val_*`，便于比较协议路径与理想路径的性能差距。

2. 时间与轮次
- `round/round`
- `round/round_time_seconds`
- `round/elapsed_time_seconds`

说明：
- `round/round` 是轮编号，从 0 开始。
- `round/round_time_seconds` 是当前轮完整结束所需时间。
- `round/elapsed_time_seconds` 是从实验启动到这一轮结束的累计耗时。

3. 当前全局模型规模
- `round/model_parameters`
- `round/model_bytes`

说明：
- 这两个字段描述的是当前聚合后全局模型本身的规模，不是这一轮真实传输了多少字节。

4. 当前轮算法有效通信量（主分析口径）
- `round/total_download_bytes`
- `round/total_download_parameters`
- `round/total_upload_bytes`
- `round/total_upload_parameters`
- `round/total_parameter_download_bytes`
- `round/total_parameter_download_parameters`
- `round/total_parameter_upload_bytes`
- `round/total_parameter_upload_parameters`
- `round/total_parameter_bytes`

说明：
- 这组字段表示算法真正为了恢复/聚合参数而必须发送的内容。
- 其中 `total_download_bytes == total_parameter_download_bytes`、`total_upload_bytes == total_parameter_upload_bytes`，属于兼容别名。
- 做算法压缩效果比较时，优先看这组字段。

5. 当前轮实际传输量（工程口径）
- `round/total_transport_download_bytes`
- `round/total_transport_upload_bytes`
- `round/total_transport_bytes`
- `round/total_transport_download_overhead_bytes`
- `round/total_transport_upload_overhead_bytes`

说明：
- 这组字段在 `parameter_*` 基础上，还包含 gRPC / envelope / 序列化等额外开销。
- 用它们看真实部署成本更合适。
- `overhead` 字段表示纯传输层额外开销，即 `transport - parameter`。

6. 压缩比、隐私与评测模式元信息
- `round/fedavg_reference_upload_bytes`
- `round/fedavg_reference_upload_parameters`
- `round/fedavg_reference_total_bytes`
- `round/parameter_upload_compression_ratio`
- `round/parameter_total_communication_ratio`
- `round/upload_compression_ratio`
- `round/total_communication_ratio`
- `round/communication_ratio`
- `round/transport_upload_compression_ratio`
- `round/transport_total_communication_ratio`
- `round/privacy_accountant`
- `round/privacy_epsilon`
- `round/privacy_delta`
- `round/privacy_rdp_alpha`
- `round/privacy_rdp_round`
- `round/privacy_rdp_total`
- `round/privacy_sampling_rate`
- `round/adaptive_clip_norm`
- `round/adaptive_clip_raw`
- `round/adaptive_clip_median_norm`
- `round/adaptive_reference_clip_norm`
- `round/adaptive_noise_std`
- `round/evaluation_mode`
- `tracking/step`

说明：
- `fedavg_reference_*` 是“如果这一轮使用稠密 FedAvg，会传多少”的参考量，用来算压缩比。
- `parameter_*_ratio` 适合做算法压缩比分析。
- `transport_*_ratio` 适合做真实传输压缩比分析。
- `privacy/*` 相关字段只有对应算法启用隐私记账时才有意义。
- `tracking/step` 与当前轮编号对齐，便于在异步写 wandb 时仍能正确定位到具体轮次。

### 6.4.2 `client/<client_id>/<ClientCommunicationRecord字段>`

`client/<client_id>/...` 表示**这一轮某个具体客户端自己的本地训练与通信情况**。它常用于分析“哪个客户端传得多、哪个客户端 loss 高、哪个客户端用了什么 payload”。

例如：
- `client/Nd2O3/loss`
- `client/CeO2/parameter_upload_bytes`
- `client/La2O3/aggregation_weight`

可以按下面 5 组理解：

1. 本地训练与聚合语义
- `num_samples`
- `loss`
- `aggregation_payload_kind`
- `evaluation_payload_kind`
- `aggregation_weight`

说明：
- `loss` 是这个客户端本地训练后的平均损失。
- `aggregation_payload_kind` 表示它真正上传给服务器参与聚合的 payload 语义，如 dense update、sparse update、quantized update。
- `evaluation_payload_kind` 只在 oracle 评测需要额外参考状态时才有意义。
- `aggregation_weight` 是服务器本轮给这个客户端分配的聚合权重。

2. 算法有效下载量
- `download_bytes`
- `download_parameters`
- `parameter_download_bytes`
- `parameter_download_parameters`
- `dense_download_reference_bytes`
- `dense_download_reference_parameters`

说明：
- `parameter_download_*` 是这个客户端本轮真正收到的算法有效下载量。
- `download_*` 是兼容别名。
- `dense_download_reference_*` 是对应稠密 FedAvg 的参考下载规模，用来做基准比较。

3. 算法有效上传量
- `upload_bytes`
- `upload_parameters`
- `parameter_upload_bytes`
- `parameter_upload_parameters`
- `dense_upload_reference_bytes`
- `dense_upload_reference_parameters`

说明：
- `parameter_upload_*` 是这个客户端上传给服务器、且算法上必须传的内容。
- `upload_*` 是兼容别名。
- `dense_upload_reference_*` 是稠密 FedAvg 参考值。

4. 实际传输量
- `transport_download_bytes`
- `transport_upload_bytes`
- `transport_download_overhead_bytes`
- `transport_upload_overhead_bytes`

说明：
- 这组字段衡量真实传输开销，不仅仅是 payload 本体。
- `overhead` 表示额外封装和序列化造成的成本。

5. 压缩器与隐私参数
- `compressor`
- `privacy_clip_norm`
- `privacy_noise_multiplier`

说明：
- `compressor` 用来区分该客户端这一轮实际采用的压缩方式。
- `privacy_clip_norm` 和 `privacy_noise_multiplier` 记录客户端侧防护参数，便于回溯实验设置是否一致。

### 6.4.3 `cumulative/<通信汇总字段>`

`cumulative/...` 表示**从第 0 轮累加到当前轮的通信总量**。它的意义不是“当前轮又传了多少”，而是“到这一轮为止，总共已经传了多少”。

这组字段非常适合：
- 画“总通信量随轮数变化”的曲线
- 直接比较不同算法在相同轮数下的累计通信成本
- 观察算法是在前期还是后期节省通信

字段集合如下：

| wandb 名称 | 含义 |
| --- | --- |
| `cumulative/last_parameter_upload_bytes` | 当前最后一轮的算法有效上传字节数 |
| `cumulative/last_parameter_download_bytes` | 当前最后一轮的算法有效下载字节数 |
| `cumulative/last_parameter_total_bytes` | 当前最后一轮的算法有效总通信字节数 |
| `cumulative/last_transport_upload_bytes` | 当前最后一轮的实际传输上传字节数 |
| `cumulative/last_transport_download_bytes` | 当前最后一轮的实际传输下载字节数 |
| `cumulative/last_transport_total_bytes` | 当前最后一轮的实际传输总字节数 |
| `cumulative/last_transport_upload_overhead_bytes` | 当前最后一轮的上传额外传输开销 |
| `cumulative/last_transport_download_overhead_bytes` | 当前最后一轮的下载额外传输开销 |
| `cumulative/last_parameter_upload_compression_ratio` | 当前最后一轮的参数上传压缩比 |
| `cumulative/last_parameter_total_communication_ratio` | 当前最后一轮的参数总通信比 |
| `cumulative/last_transport_upload_compression_ratio` | 当前最后一轮的实际传输上传压缩比 |
| `cumulative/last_transport_total_communication_ratio` | 当前最后一轮的实际传输总通信比 |
| `cumulative/total_parameter_upload_bytes` | 截至当前的累计参数上传字节数 |
| `cumulative/total_parameter_download_bytes` | 截至当前的累计参数下载字节数 |
| `cumulative/total_parameter_bytes` | 截至当前的累计参数总通信字节数 |
| `cumulative/total_transport_upload_bytes` | 截至当前的累计实际传输上传字节数 |
| `cumulative/total_transport_download_bytes` | 截至当前的累计实际传输下载字节数 |
| `cumulative/total_transport_bytes` | 截至当前的累计实际传输总字节数 |
| `cumulative/total_transport_upload_overhead_bytes` | 截至当前的累计上传额外传输开销 |
| `cumulative/total_transport_download_overhead_bytes` | 截至当前的累计下载额外传输开销 |

### 6.4.4 攻击 wandb 标量字段

`attack/...` 表示**攻击线程在某一轮结束后写回的隐私评估结果**。它和训练主流程分离，所以主要用于观察“攻击重构效果是否在变差”“不同方法是否更难被还原”。

先看所有攻击方法合并后的 round 级统计：

| wandb 名称 | 含义 |
| --- | --- |
| `attack/round_index` | 这一批攻击对应的联邦轮 |
| `attack/time_seconds` | 这一批攻击总耗时 |
| `attack/evaluations_this_round` | 这一轮实际执行的攻击次数 |
| `attack/clients_this_round` | 这一轮被攻击的客户端数量 |
| `attack/samples_per_client` | 每个客户端抽取多少个样本做攻击 |
| `attack/primary_metric_name` | 当前实验采用的攻击主指标名 |
| `attack/overall_avg_primary_metric_so_far` | 截至当前所有攻击结果的主指标平均值 |
| `attack/overall_avg_mse_so_far` | 上一项的兼容别名 |
| `attack/success_rate_so_far` | 截至当前所有攻击结果的累计成功率 |

再看按方法拆开的统计，`<method>` 典型值为 `DLG`、`iDLG`：

| wandb 名称 | 含义 |
| --- | --- |
| `attack/<method>/primary_metric_name` | 该方法当前使用的主指标名 |
| `attack/<method>/primary_metric` | 该方法在当前这一轮攻击批次中的平均主指标值 |
| `attack/<method>/mse` | `primary_metric` 的兼容别名 |
| `attack/<method>/reconstruction_mse` | 同上，强调其可能是重构误差视角 |
| `attack/<method>/avg_primary_metric_so_far` | 截至当前该方法累计主指标平均值 |
| `attack/<method>/avg_mse_so_far` | 上一项的兼容别名 |
| `attack/<method>/psnr` | 当前这一轮该方法平均 PSNR |
| `attack/<method>/ssim` | 当前这一轮该方法平均 SSIM |
| `attack/<method>/iterations` | 该方法单次攻击优化步数配置 |
| `attack/<method>/time_seconds` | 当前这一轮该方法平均攻击耗时 |
| `attack/<method>/objective_mse` | 当前这一轮该方法平均目标函数误差 |
| `attack/<method>/gradient_mse` | `objective_mse` 的兼容别名 |
| `attack/<method>/success` | 当前这一轮该方法平均成功率（0~1） |
| `attack/<method>/success_rate_so_far` | 截至当前该方法累计成功率 |

读取建议：
- 想看“现在攻击难不难”：看 `attack/<method>/primary_metric`
- 想看“整体越来越难还是越来越容易”：看 `attack/<method>/avg_primary_metric_so_far`
- 想看“成功率是否下降”：看 `attack/<method>/success_rate_so_far`
- 想比较不同方法当前轮的恢复质量：同时看 `primary_metric`、`psnr`、`ssim`

## 7. 备注

1. `summary.json` 适合做最终结果对比。
2. `metrics.json` 适合画收敛曲线与逐轮通信分析。
3. 如果关注算法本身压缩率，优先读取 `parameter_*`。
4. 如果关注真实网络传输成本，优先读取 `transport_*`。
5. 对 EGA 而言，下载 `round_context` 中的恢复辅助信息已经计入 `parameter_download_*`，不再只体现在 `transport_*`。
